# Slack is where work is done; the app is where it is signed

**Status:** accepted. Supersedes [ADR 0002](0002-slack-runs-alongside-email-until-reliable.md). **Revised 2026-11-18 by plan P-58:** work is now done in Slack by talking to an Agent, not only started there, and the content line is PHI ([ADR 0005](0005-phi-never-leaves-the-app-slack-mirrors-teams.md), superseding ADR 0004). The Assistant (P-40, hidden by P-56) is deleted: the Agent replaces it, so the retirement bar this ADR used to set no longer applies. The Slack demo (plan P-57) keeps working inside this boundary.

Slack becomes the main place people do their work. A Slack app (Socket Mode, so no public address) gives each person an App Home with their Tasks, a DM for each notice, the `/adj` command, and one Agent in the app's Messages tab that each person talks to. The Agent acts as that person and sees exactly what that person sees in the app, enforced by code in its tools rather than by its prompt. It answers questions and does the steps that need no signature: the data manager's import and pull, the site's upload of files attached to the conversation, and the Safety Specialist's edits to the Narrative draft and draft Site Query, both unsigned drafts that the app's Quality check page opens with. A notice's DM starts a Conversation: a reply in its thread reaches the Agent with that case as context. Every signed step is finished in the app through an *Open in the app* button: the site's signature, the Quality Check, adjudication and more-data requests, the committee meeting and the Chair's consensus, re-adjudication, entering an AE by hand. Slack advises against asking for passwords "within modals (or any app surface area)" and has no masked input, so no signature is taken in Slack. The app also keeps the screens Slack cannot show well: document previews and the redaction review, the Case record and measurement. E-mail continues for every notice and the app keeps every screen, so the workflow never depends on Slack or on AI: with both off it still runs from the app and e-mail, and a failed DM is a recorded Delivery Attempt. Flows 3 and 4 have no AI (P-49), so adjudicators, the CEC Coordinator and the committee get Tasks and status from the Agent, not case content. Pharma users live on Teams, so the same boundary applies to a Teams app later.

## Consequences

- In the demo, a Slack account maps to a person through `slack_user_id` in `users.yaml`; otherwise one account is Acting As each person through `/adj act-as`, simulated as the app's sidebar is.
- Every Slack action is written to a hash-chained `data/slack/actions.jsonl`, and every turn with the Agent to a hash-chained `data/slack/conversations.jsonl`, with the Slack user ID; case events stay as they would be from the app, recorded as the person acted for.
- The Agent is Claude through the AI gateway only, with its own AI mode so it can run live while the Quality Check agents stay on replay.
